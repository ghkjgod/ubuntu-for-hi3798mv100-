# EC6108V9C 实测：wiliwili 播放 B 站 H.264 B 帧

2026-11-21，在 Hi3798MV100 真机 Ubuntu 24.04 armhf、Linux `6.12.114-hi3798-mv100-exp` 上验证。安装包版本为 `1.6.0-1+mv100.7`。普通桌面启动器以用户 `desktop`（UID 1000）运行客户端；进程映射确认使用包内的私有 libmpv。VDH 模块已在物理断电重启后自动加载，SSH 已启用并能连接。最终 mv100.7 包通过 SSH 安装后，重新启动客户端并复测两档视频及软件回退；物理冷启动时使用的是同一模块和 mv100.6 客户端。

## B 站实播

样片为 BV1GJ411x7h7，CID 137649199，官方 DASH AVC，25 帧/秒。720p 与 1080p 均含 B 帧、6 个短期参考、P 帧加权和 B 帧隐式加权。取流使用访客接口。客户端访客页面自动选择的清晰度是 360p。为固定验收的清晰度，在运行中的同一个 wiliwili 进程通过 libmpv IPC 分别打开官方 720p/1080p 视频流和配套 AAC 音轨，跳转到第 42 秒采样。测试没有通过 IPC 指定解码器。显示环境为 1920×1080、60 Hz 桌面和 1280×720 播放窗口。

两档都报告 `V4L2 mem2mem H.264 decoder wrapper`、NV12、AAC、ALSA。每次采样期间 VDH 的拒绝和错误计数增量、libmpv 解码丢帧增量均为 0。图像检查可见正常视频场景，前后画面随播放变化。下表保留 VO 层实际丢帧，分母取播放器的帧序号差。VDH 和播放帧序号在观察窗口两端受缓冲影响，计数可以略有差异。

播放由海思 VDH 解码。当前输出仍需整理线性 NV12 并通过 libmpv 和桌面显示。关闭弹幕能减少这台机器实测的显示丢帧，桌面仍未达到源视频的连续 25 帧/秒。采样来自短时播放窗口。

## 逐帧校验

在真机上将上述同一对官方码流的开头（128 帧）和后段运动画面（328 帧）分别解码为 NV12。软件基准使用 FFmpeg H.264，硬件使用与 wiliwili 相同的 FFmpeg `h264_v4l2m2m` 接口。按显示顺序逐帧计算 SHA-256，并比较整份摘要列表。两档均有 **456 / 456 帧像素及顺序完全相同**。下表为逐帧清单自身的 SHA-256。

| 清晰度 | 片段 | 帧数 | 软件和硬件清单共用的 SHA-256 |
| --- | --- | ---: | --- |
| 720p | 开头 | 128 | `3de3719de47908d09752c896fae147f5ed91d9da07a02f0c4dfc01b17870ae70` |
| 720p | 运动画面 | 328 | `0772ca0fbcd57e9df4448dddaad0daef1ae8e07bcd1c3ca9068a3a5674cf7b70` |
| 1080p | 开头 | 128 | `052a3ae482e9a06a1bb48bcf57bd96c1b97c7480e169f6874d14cddeef182c7b` |
| 1080p | 运动画面 | 328 | `074df1f3ecf2c6480a743c31245f8a914fe1fddd10265e4c69fc79bd1654d5ad` |

独立的合成 H.264 B 帧回归在有状态和 Request 两个接口各通过 48/48 帧；原有单参考 H.264 和 HEVC Main I/P 各通过 24/24 帧。额外检查 GStreamer Request 接口时，真实样片的开头通过 128/128 帧，运动片段的 GStreamer 管线输出了 326/328 帧，输出的帧均匹配，VDH 计数增加 328。wiliwili 使用的有状态接口输出了完整尾帧。

## 回退和交付

在播放正常的 720p 硬解视频时切换到驱动不支持的 160×128、多 slice H.264。VDH 拒绝后，客户端自动选择 FFmpeg 软件解码并恢复播放，连续采样的位置从 0 前进到 2.917 秒。最终包通过 `dpkg -V wiliwili`。SSH 在最后一次检查时为 enabled、active。正常关机后经只读串口确认内核停止，继电器读回 GPIO25=0。
